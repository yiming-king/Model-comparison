# Model-comparison benchmark

Research code for studying neural posterior estimation (NPE), Bayesian model
comparison, and diagnostics for detecting unreliable posterior and model-evidence
approximations.

The repository currently contains two main case studies:

- `benchmark/examples/gaussian/`: Gaussian/Student-t benchmark with analytical
  and Stan reference results.
- `benchmark/examples/diffusion/`: four-model racing-diffusion benchmark using
  Wagenmakers data, NPE, Stan, bridge sampling, summary-space diagnostics, and
  well-specified NPE-MCMC calibration.

## Terminology

Two model roles are kept separate throughout the repository:

- **Generating/source model**: the model used to generate an observed dataset.
- **Candidate/assumed model**: the model under which posterior inference and
  marginal-likelihood estimation are performed.

For example, a dataset generated by `m0` can still be evaluated under all four
candidate models `m0`–`m3`.

## Installation

Python 3.10–3.12 is supported. From the repository root:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev,notebooks]"
```

The local development environment used for the diffusion case study is:

```text
/opt/anaconda3/envs/benchmark2/bin/python
```

Stan fitting and bridge sampling additionally require R with:

- `rstan`
- `bridgesampling`
- `jsonlite`

## Diffusion case study

The main implementation is in `benchmark/examples/diffusion/`:

| Path | Purpose |
| --- | --- |
| `dataset/` | Load and preprocess Wagenmakers data; generate clean and contaminated datasets. |
| `simulators/` | Racing-diffusion simulators for models `m0`–`m3`. |
| `distributions/` | Prior and likelihood implementations matching the Stan models. |
| `networks/` | NPE inference and summary-network definitions. |
| `approximators/` | Train, save, and load NPE approximators. |
| `stan/` | Unified four-model Stan program and bridge-sampling runner. |
| `results/` | NPE logML/PMP estimation, posterior diagnostics, summary diagnostics, and plotting. |
| `calibration/` | Well-specified calibration pipeline and threshold aggregation. |
| `notebooks/` | Analysis and visualization entry points. |

### Data representation

Each dataset contains 384 trials. Python analyses use arrays with shape
`(datasets, 384, 2)`, where the last dimension is signed response time and
experimental condition. Stan uses the equivalent JSON representation:

```json
{"rt": [], "condition": [], "N": 384}
```

Positive response times denote correct responses, negative values denote
incorrect responses, and conditions are coded as speed `1` and accuracy `0`.

Generate the standard simulated and contaminated dataset suites with:

```bash
python -m benchmark.examples.diffusion.dataset.generate_synthetic
python -m benchmark.examples.diffusion.dataset.generate_contaminated
```

Both generators protect existing output unless `--overwrite` is supplied.

### Train NPE models

Train the four models for several summary-dimension multipliers:

```bash
python -m benchmark.examples.diffusion.approximators.train_grid \
  --summary-multipliers 1 2 4 6
```

For networks trained without the summary-MMD loss:

```bash
python -m benchmark.examples.diffusion.approximators.train_grid \
  --summary-multipliers 1 2 4 6 \
  --no-summary-mmd \
  --run-suffix noMMD
```

### Stan and bridge-sampling references

`benchmark/examples/diffusion/stan/rdm_4_models.stan` contains all custom Wald
and racing-diffusion functions and represents all four candidate models through
`model_index`.

`benchmark/examples/diffusion/stan/fit_4_models.R` writes, for each dataset and
candidate model:

- bridge-sampling log marginal likelihoods;
- convergence diagnostics;
- full fitted Stan objects;
- lightweight posterior-draw CSV files for Python diagnostics.

These outputs are generated artifacts and are excluded from Git tracking.

### NPE results and diagnostics

The main results modules have distinct responsibilities:

```text
observed_datasets.py
        |
        v
multisource_pipeline.py
        |-- results.py               -> NPE logML, PMP, ESS, and MCMC errors
        |-- posterior_diagnostic.py  -> raw NPE-MCMC posterior MMD
        `-- summary_diagnostic.py    -> L2, Linf, MMD, and density diagnostics
                         |
                         v
summary_dimension_comparison.py     -> cached-result comparisons and figures
```

`results.py` and `posterior_diagnostic.py` are reusable calculation modules.
`multisource_pipeline.py` coordinates empirical, clean simulated, and
contaminated datasets. At present this results pipeline is called from Python or
the notebooks rather than through a command-line interface.

For example:

```python
from benchmark.examples.diffusion.config import TrainingConfig
from benchmark.examples.diffusion.results.multisource_pipeline import (
    compute_or_load_all_observed,
)

result = compute_or_load_all_observed(
    TrainingConfig(
        summary_multiplier=4,
        summary_base_distribution=None,
        run_suffix="noMMD",
    ),
    metric="l2",
)
```

### Well-specified threshold calibration

Calibration is isolated from the empirical/OOD result pipeline:

```text
generate well-specified datasets
        -> fit all candidate models with Stan and bridge sampling
        -> calculate per-dataset NPE-MCMC MMD, logML, and PMP errors
        -> filter non-converged fits and calculate 95% thresholds
```

The complete workflow can be run directly from the repository root:

```bash
python benchmark/examples/diffusion/calibration/pipeline.py all
```

Individual stages are also available:

```bash
python benchmark/examples/diffusion/calibration/pipeline.py generate
python benchmark/examples/diffusion/calibration/pipeline.py mcmc
python benchmark/examples/diffusion/calibration/pipeline.py metrics
python benchmark/examples/diffusion/calibration/pipeline.py thresholds
```

The `metrics` stage writes:

```text
benchmark/examples/diffusion/calibration_outputs/per_dataset_metrics.csv
```

Thresholds can then be rebuilt without rerunning NPE or MCMC:

```bash
python benchmark/examples/diffusion/calibration/thresholds.py
```

This writes:

- `calibration_outputs/thresholds.csv`;
- `calibration_outputs/per_dataset_results.csv`.

The three default thresholds are the 95th percentiles of:

- matching-model NPE-MCMC posterior MMD from converged fits;
- matching-model absolute NPE-versus-bridge logML error from converged fits;
- all four absolute PMP-component errors for datasets on which all candidate
  models converged.

No MCMC-MCMC null threshold is used.

## Gaussian case study

`benchmark/examples/gaussian/` contains the Gaussian/Student-t experiments,
including analytical posterior and marginal-likelihood calculations, NPE/NPMP
experiments, Stan references, OOD diagnostics, and summary-dimension notebooks.

In the original three-model setup:

- `M1`: Normal prior mean 0 with a Normal likelihood;
- `M2`: Normal prior mean 0.5 with a Normal likelihood;
- `M3`: Normal prior mean 0 with a Student-t likelihood (`df=5`).

Additional source models are used for open-world/OOD observations. File names
identify the source model, while result columns such as `gold_post_samples_m3`
or `gold_log_marginal_m3` identify the assumed model.

## Generated artifacts and Git

Large or reproducible artifacts are intentionally ignored, including:

- trained NPE models, histories, and logs;
- generated dataset JSON files;
- Stan fits, posterior draws, and bridge-sampling output;
- calibration output trees;
- cached result tables and plots;
- local spreadsheet exports, PCA/PPC experiments, and temporary presentation
  material.

Consequently, a fresh clone contains the source code but not every local result
needed by downstream notebooks. Generate the required upstream artifacts before
rebuilding an analysis.

## Tests

Run the diffusion calibration unit tests with:

```bash
pytest -q tests/test_diffusion_calibration.py
```

The tests cover model-prior handling, MCMC convergence filtering, logML base
conversion, and diagnostic classification definitions.
